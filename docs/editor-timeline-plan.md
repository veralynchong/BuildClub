# 剪輯器改成多軌時間軸：計畫

日期：2026-11-12。狀態：草案，等使用者確認。
研究筆記：`research/research_notes/剪輯器時間軸介面/timeline_editors.md`（13 張截圖、各家版面、授權與價格，2026-11-12 讀取）。
前一份計畫：`docs/ai-edit-plan.md`（Phase 0–4，PR #56）。

## 範圍

- 只改剪輯器：`src/components/editor/*`、`src/lib/editor/*`、`src/remotion/*`、剪輯器樣式，以及 `backend/analysis.py`（加波形資料）。
- 不動：Canvas、規劃板、Plan 頁版面、AI 生成。
- 不做手機版。影片內容只做英文。

## 現況與目標

| | 現在 | 目標 |
|---|---|---|
| 時間軸 | 只有一條影片道（`Timeline.tsx` 305 行），下面是每段的音量列 | 五條道：文字、字幕、影片、旁白、音樂 |
| 字幕、文字、旁白、音樂 | 只在右側分頁裡，時間軸上看不到 | 畫成時間軸上的彩色條，可拖曳、拉長短 |
| AI 建議 | 只在「AI 建議」分頁的清單裡 | 直接標在影片條上，點一下選保留或刪除 |
| 右側面板 | 手動切換七個分頁 | 點時間軸上的條，自動切到對應分頁並定位 |
| 片段外觀 | 純色塊 | 縮圖條加音訊波形 |
| 文字稿 | 無 | 左側可切換成文字稿：點字跳播放頭、改字、刪字就剪掉那段 |

資料模型 `EditProject` 已經有 `texts[]`（start/end）、`captions.speech[]`、`voiceover[]`（start）、`music`，所以大部分只是把現有資料畫出來，後端 schema 幾乎不變。

## 版面

參考 Kapwing、VEED、Clipchamp（截圖 07、08、09、10）：

- 左：分鏡素材（不變），上方多一個「分鏡 / 文字稿」切換。
- 中：Remotion Player 預覽（不變）。
- 右：工具分頁（不變），改成會跟著選取切換。
- 下：時間軸工具列（分割、吸附開關、縮放、符合畫面）加五條道。

## 階段

| 階段 | 內容 | 估計 |
|---|---|---|
| T1 多條道 | 文字、字幕、旁白、音樂畫成條；點條就選取並切到右側對應分頁；文字和字幕條可拖曳、拉長短；每條道可隱藏、靜音 | 2 天 |
| T2 吸附與操作 | 吸附到片段邊緣、播放頭、字幕邊界，可開關；符合畫面；播放時畫面跟著播放頭；快捷鍵：空白鍵播放、S 分割、Delete 刪除、←→ 逐格；AI 還原改成多步 | 1 天 |
| T3 時間軸上的 AI 標記 | 靜音、贅詞、重拍以斜線色塊標在影片條上；點一下選保留或刪除；初剪的理由變成小圖釘 | 1.5 天 |
| T4 縮圖條與波形 | 後端分析多存一份音訊波形資料；前端用現有縮圖畫縮圖條，加上波形 | 1.5 天 |
| T5 文字稿視圖 | 左側切成文字稿，點字跳播放頭，播放時高亮目前的字；改字會更新字幕；刪字等於剪掉那段（沿用 `suggest/keeps`） | 2 天 |

合計約 8 個工作天。

建議：T1–T3（4.5 天）在測試者下週試用前完成；T4–T5 等第一輪回饋後再做。

## 2026-11-12 重新估時（照 AI 實際速度）

上表的「天」是照人類工程師估的。實際上 T1–T5（估 8 天）在 2026-11-12 一天內全部做完（stage A、B、C，PR #57），沒有記錄每段實際花幾分鐘。以後每段做完都在 STATUS 記下實際耗時。

剩下的是已知問題和上線準備：

| 項目 | AI 做的時間 | 實際 |
|---|---|---|
| 初剪圖釘跟著剪輯移動 | 約 30 分鐘 | 2026-11-12 完成 |
| 軌道隱藏／靜音也套用到匯出（存進專案 `lanes`） | 30–60 分鐘 | 2026-11-12 完成，含程式和測試約 1 小時 |
| 剛開剪輯器第一次點字沒跳轉 | 15 分鐘到 1 小時以上（原因未知） | 未做 |
| 每次 `verify.sh full` | 約 1 分鐘（2026-11-12 量到 58 秒） | |
| 每次瀏覽器實測 | 10–20 分鐘 | |

真正卡時間的是人和外部：使用者實測（15–30 分鐘）、Veralyn review 並依序合併 #56 → #57 → #58（關鍵路徑）、demo day 分支要不要合、團隊人數（Remotion 授權）。11/16 送測試者，寫程式的部分不是瓶頸。

## 每個階段的規則

和 `docs/ai-edit-plan.md` 相同：verify full GREEN，在隔離後端開 1440 寬瀏覽器走過一遍，commit 並 push，PR 不合併。

## 不做

- 買 Remotion Editor Starter（US$600）或 Timeline 元件（US$300）。兩者都需要 Tailwind，Remake 沒有用 Tailwind；整合成本比自己延伸 `Timeline.tsx` 高。
- 拷貝 OpenChatCut（AGPL）或 openvideodev（自訂授權、引擎不是 Remotion）的程式碼，只參考它們的操作方式。
- 關鍵影格、轉場、特效。
- 在畫面上自由拖曳、旋轉、裁切文字。
- 多人協作、留言游標。
- 對話式 AI 剪輯、爆紅分數。
- 手機版。

## 風險

- 時間軸大改後，測試者看到的是剛改好的介面。每個階段做完都要能單獨上線，T3 沒做完也不會擋 T1–T2。
- 字幕條的時間是按字數比例估的（已知問題），拖曳字幕條時會覺得不準。T5 改用逐字時間後才會改善。
- 研究只看了各家的行銷圖和說明文字，沒有實際操作。
- Remotion 授權：團隊 4 人以上，做剪輯器屬 Automators（每次渲染 US$0.01，每月最低 US$100），不管有沒有改時間軸都適用，上線前要確認團隊人數。
