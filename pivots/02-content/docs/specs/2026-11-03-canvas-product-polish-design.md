## 1. 為什麼做

畫布功能大多已經能用（Shot → 分鏡圖 → 影片 → 時間軸 → 剪輯器 → 匯出／送審），但看起來像原型。使用者最在意的是「整個 UI 設計，尤其是線」，接在一起的線讓整張畫布「感覺很假」〔使用者〕。參考對象是 Flora，因為「看起來最成熟」〔使用者〕。

第一個使用者是使用者本人做 user test〔使用者〕。所以這一輪的成功標準是：從核可的計畫走到送審，整條路順、每個狀態都看得懂、畫面像真產品；不是 demo 用的亮點功能。

## 2. 目標、非目標、反目標

**目標**
1. 外殼像產品：上方工具列、窄側欄、全螢幕模式、左側浮動工具列、右側參數面板、佇列、minimap（§4）。
2. 線和節點不再「假」：shot 變成框、細線、明確的狀態（§5、§6）。
3. 時間軸留在畫布上：Timeline 節點，細剪時進全螢幕（§7）。
4. 修好研究找到的斷點：送審第一次就能送、Start frame 自動接、入口視角、按鈕文字（§8）。
5. 最小版 AI 代理：替一個 shot 建好節點鏈並報價，核准才跑（§9）。

**非目標（這一輪不做）**
- 深色模式〔使用者選淺色〕。
- 範本、「一句話起手」的入口。
- AI 代理的整個計畫一次處理、自由對話、用一句話改現有節點。
- 分支樹式的版本（Flora 那種）。
- 手機版（專案記憶：2026-11-02 起不做 390 寬優化）。
- 多軌時間軸（畫布規格 §2 非目標，照舊）。

**反目標（做到了也算失敗）**
- 線多到蓋住畫面、或線穿過不相干的節點。
- 任何會花錢的動作沒先顯示價格（畫布規格反目標，照舊；AI 代理也適用）。
- 按一個按鈕整頁跳走，回來看不出剛才做了什麼。
- 為了好看把現有能力拿掉：版本、過期標記、套組、實拍節點、每日上限都要保留。

## 4. 外殼〔使用者選「淺色、保留窄側欄」+ 全螢幕切換〕

### 4.1 版面
- **Remake 側欄**：進畫布時縮成只有圖示（約 44px），離開畫布恢復〔使用者〕。
- **上方工具列**（固定，約 40px）〔我的決定，使用者在草圖上看過〕：
  - 左：「←」回計畫、計畫標題、客戶名（淡色小字）。
  - 中：Canvas／Timeline 切換（Timeline = 進入 §7.2 全螢幕剪接）。
  - 右：整支總價「N shots · ≈ US$x.xx」（§6.4）、Run all、Send for approval、全螢幕鈕。
- **全螢幕模式**〔使用者〕：隱藏 Remake 側欄和瀏覽器以外的所有 app 外框，只留上方工具列和畫布。工具列的鈕切換，快捷鍵 `F` 進入、`Esc` 離開〔我的決定〕。記住使用者上次的選擇（localStorage）〔我的決定〕。
- **左側浮動工具列**：選取、拖曳畫面、新增節點、✦ AI 代理〔我的決定，照 Flora〕。新增節點選單就是現在右上「Add」的內容，搬過來。
- **右側參數面板**（§6.3）：選取一個生成節點時出現，沒選取時收起。
- **左下**：佇列「● N running · 約 X 分鐘」，點開列出正在跑的節點，點一個就跳過去〔我的決定〕。
- **右下**：縮放控制（−、百分比、＋、fit）和 minimap。

### 4.2 進入
- 不論從側欄或計畫頁「Open the canvas」進入，都先 fitView〔研究：側欄進入目前放大 2 倍、右半被裁切〕。
- 頁面標題是計畫名稱，不是「Canvas」。
- 多個核可計畫時的選擇頁，每張卡加上 shot 數與狀態（例如「3 shots · 1 ready」）〔我的決定〕。

## 5. 線與 shot 框〔使用者選「B + shot 變成框的標題」〕

### 5.1 Shot 變成框
- Shot 不再是一個節點，改成一個框（React Flow 的 group／parent node 或自畫背景，〔交給實作者〕）。框的標題列：「Shot N」、用途與長度 chip（例如「Hook · 3s」）、台詞或鏡頭描述（單行，過長省略，hover 看全文）、狀態 chip（「✓ main clip」）、「✦ 幫我建好」（§9）。
- 框裡放這個 shot 的生成節點、上傳、實拍節點。框隨內容自動長大〔交給實作者〕。
- 原本 Shot 節點的「文字」輸出（接到分鏡圖、影片的 Text 埠）改成**隱含**：框裡的分鏡圖和影片節點自動使用這個 shot 的文字當 prompt 的基礎，不畫線〔我的決定〕。節點上用一行淡字說明「用 Shot 1 的文字」，可以在右側面板改寫或關掉。Prompt 節點仍然可以加，接上就取代 shot 文字。
- 原本 Shot 節點的「+」選單搬到框標題列右側。
- shot list 刪除的 shot（現在的 `removed`）：框變灰、標題加「已從計畫刪除」，不刪裡面的生成結果（畫布規格 §4.3，照舊）。

### 5.2 線的樣式
畫布規格 §5「依媒體上色（三色）」改成以下規則〔使用者看過草圖〕：
- 平常：約 1.4px 的中性灰細線（用 token），平滑曲線。
- 選取一個節點：它的上下游線變成主色藍。
- 正在生成：那條線藍色、虛線流動（尊重 `prefers-reduced-motion`，關掉動畫）。
- 上游還沒有結果（例如影片接到 Timeline，但影片還沒生成）：灰色虛線、較淡。
- 套組的線照套組規格 §5.1：淡色，選中套組節點時才明顯。
- 線不得穿過節點；同一個 shot 內 Storyboard → Video 是短的水平線。

### 5.3 埠
- 埠是節點邊上的小圓點（約 10px）。媒體類型用圓點的邊框顏色區分（文字／圖／影片），線本身不上色〔我的決定：保留型別資訊，又不讓線變花〕。
- 埠的名稱（Reference、Start frame、Prompt）hover 才出現，不再浮在線旁邊。
- 拖線時相容的埠亮起、不相容的變灰（現有行為，保留）。從輸出埠拖到空白處放開，跳出只列相容節點的選單，選了就建立並接好〔研究：Node Banana〕。

### 5.4 自動接線
- 在 shot 框裡新增影片節點時，自動把同一框裡的分鏡圖接到 Start frame〔研究：我們目前不會自動接〕。框裡有多個分鏡圖時接最新建立的那個〔我的決定〕。
- 新的影片節點自動接到 Timeline 節點（§7.1）只在它成為 main clip 時發生，不是一建立就接〔我的決定〕。

## 6. 節點

### 6.1 生成節點（分鏡圖、影片）
草圖上的樣子〔使用者看過〕：
- 寬度約 180px（現在約 220px 但字很小、內容被截斷；實際寬度〔交給實作者〕，條件是模型名、價格不被截斷）。
- 標題列：類型名稱，右側一個狀態文字：版本「v2 / 3」、「生成中 · 約 2 分鐘」、「等 Storyboard」、「還沒生成」、「過期」、「失敗」。同一時間只顯示一個狀態〔研究：現在失敗時紅字、Out of date、舊影片、Try again 四件事同時出現〕。
- 中間：結果大圖或可播放的影片；沒有結果時是淡色佔位；生成中是斜線條紋。點結果可放大檢視。
- 底部：模型短名、「≈ $0.52」。
- 已在時間軸上的影片節點，底部或角落一個綠色「✓ 在時間軸」〔研究：Dreamina〕。
- 節點上的主要按鈕：沒結果時「Generate」，有結果後「Regenerate（v4）」〔研究〕。失敗時「Try again」。

### 6.2 其他節點
Prompt、Upload、Footage、Kit 套用同樣的卡片外觀（圓角、陰影、標題列、埠）〔我的決定〕。Kit 節點的內容照套組規格。

### 6.3 右側參數面板
選取一個生成節點時出現〔使用者看過草圖〕：
- 標題「Video · Shot 1」。
- 欄位：模型（自訂下拉，每行全名、≈US$、預估等待時間、檔位徽章「便宜／平衡／最好」〔研究：Flora、LTX〕；取代現在的原生 select）、長度、起始畫面（顯示來源節點與版本）、prompt（可編輯；顯示「用 Shot 1 的文字」的狀態）、套組勾選（分鏡圖，照套組規格 §5.2）。
- 價格與等待時間一行：「≈ US$0.52 · 約 2 分鐘」。
- 版本：一排縮圖，點一下切換，目前選用的有框；hover 顯示建立時間和模型〔研究：Weave、Runway〕。另有「用這版的設定重做」〔研究：Runway Reuse prompt and settings〕。
- 底部主按鈕：「Regenerate（v4）」或「Generate」。
- 節點上原本的設定控制項搬到這裡，節點本身只留結果和摘要〔我的決定，Flora 做法〕。

### 6.4 價格
- 上方工具列的整支總價：所有 shot 目前設定下「還沒有結果的節點」的預估總和〔我的決定〕；改模型或長度即時更新。hover 顯示每個 shot 的小計和「今天還剩 US$x」。
- 付費節點的第一次單點 Generate 也要確認，之後同一個 session 不再問〔研究：目前只有「Run the whole shot」有確認〕。
- 「Run all」照現在「Run the whole shot」的確認窗，但範圍是所有 shot〔我的決定〕；確認窗列出每個 shot 的小計和總額。

### 6.5 執行中
- 節點上顯示預估剩餘時間（模型清單裡加每個模型的典型等待秒數〔我的決定〕；沒資料時只顯示經過時間）。
- 左下佇列（§4.1）。
- 生成中可以取消嗎：〔交給實作者，看提供商 adapter 是否支援；不支援就不放按鈕〕。

## 7. 時間軸〔使用者選「時間軸當節點，細剪時進全螢幕」〕

### 7.1 Timeline 節點
- 每張畫布一個 Timeline 節點，放在所有 shot 框的右邊，不能刪〔我的決定〕。
- **一個 shot 只有一段進時間軸**〔使用者，2026-11-03 選項 1〕：每個 shot 的 main clip 自動接進來，順序照 shot 順序。「Add to timeline」與「Make this shot's main clip」合成一個按鈕「放進時間軸」；按另一個版本或另一個節點就換掉這個 shot 原本那段。上傳或實拍的影片要進時間軸，也是設成該 shot 的那一段。
- 舊的剪輯專案若同一個 shot 有多段：載入時保留標成 main clip 的那段，沒有標的保留時間軸上第一段，其餘移除並在 toast 說明一次〔我的決定〕。
- 節點內容：可播放的預覽（9:16 縮小）、一排片段色塊（標「Shot 1 · v3」）、字幕軌一行；還沒準備好的 shot 用斜線佔位；標題「Timeline · 13s」和「1 / 3 ready」。
- 節點底部：「⤢ 展開剪接」、「Export ▾」。
- 加入時間軸時，畫布上只出現一個 toast「已放進時間軸 · 開啟剪接」，不跳頁〔研究：現在整頁跳走〕。

### 7.2 全螢幕剪接
- 從 Timeline 節點「展開剪接」或上方工具列切到「Timeline」進入；用同一個切換或「← 回畫布」回去，回到原本視角（現有行為，保留）。
- 版面〔使用者看過草圖〕：左邊各 shot 的片段與版本、中間預覽、右邊選中片段的設定（長度、轉場、字幕開關、「↗ 跳到畫布節點」）、下方時間軸（單軌片段 + 字幕層 + 音樂層，照畫布規格 §8）。
- 現在的 5 步驟列改成這個畫面裡的分頁（Clips、Captions、Music、Brand…），做完才打勾，不預先打勾〔研究〕。
- 片段名稱帶 shot 與版本，不再全部叫「Clip · Generated · 4s」〔研究〕。
- 時間軸片段右鍵或右側面板「跳到畫布節點」：回畫布並選取、置中那個節點〔研究：Flora〕。
- 匯出和送審在這個畫面的上方工具列；匯出面板不要蓋住右側分頁〔研究〕。

畫布規格 §4.2「剪輯器是右側抽屜、畫布縮窄」改成本節。

## 8. 修斷點

1. **送審**：送出時如果審閱連結沒開，直接替使用者開一個再送出；如果因權限開不了，同一個面板上給「建立連結」按鈕。錯誤文字不得再提「Shortlist」，改指 Plans 看板的「Get link」〔研究，使用者同意列為最優先〕。
2. **按鈕文字**：有結果後「Regenerate（vN）」（§6.1）。
3. **版本外溢**：研究時觀察到一次「只按影片的 Generate，分鏡圖也多一個版本」，乾淨重拍沒重現。實作時加一個測試確認只會新增被按的那個節點的版本〔我的決定〕。
4. **入口視角、標題**：§4.2。

## 9. AI 代理（最小版）〔使用者選最小版〕

### 9.1 原則改變〔使用者，2026-11-03〕
在畫布上，AI 可以替使用者寫內容（分鏡圖 prompt、影片設定）。分析真實影片那段（`assist.py`、`analyze.py`）照舊只描述。要在 `docs/decision-log.md` 記一條，並更新 `assist.py` 開頭的註解範圍。

### 9.2 流程
1. 入口：shot 框標題列「✦ 幫我建好」，或左側工具列 ✦ 後選一個 shot。
2. 代理讀這個 shot 的資料（用途、長度、台詞或描述、計畫的其他 shot 當上下文、這張畫布的套組項目），提出：
   - 分鏡圖：prompt、模型。
   - 影片：prompt（動作描述）、模型、長度。
3. 在右側面板顯示「計畫」：每個節點一張卡（prompt 可直接改、模型可換）、每個節點價格、總價。不直接執行〔研究：Krea Node Agent〕。
4. 使用者選：「核准並執行」（建立或更新節點、接好線、照 §6.4 確認後開始跑）、「只建立不執行」、「取消」。
5. 框裡已經有節點時，代理更新這些節點的設定，而不是再建一組〔我的決定〕；有結果的節點不會被覆蓋，新的設定會在下次 Regenerate 時用。

### 9.3 技術
- 後端一個新路由，沿用 `shotlist.py` 呼叫 Claude 的方式：同一個 client、結構化輸出（Pydantic）、每日花費錢包與上限、沒有 key 或 mock 模式時回傳範例計畫（user test 不花錢）〔我的決定〕。
- 使用的 Claude 模型〔交給實作者〕：選便宜的（例如 `claude-haiku-5-5`）；寫 prompt 品質不夠再換。
- 代理只能從模型清單（`backend/gen_models.json`）裡選模型，選不到的值後端拒絕〔我的決定〕。
- 代理每次呼叫的費用要算進每日上限，並在計畫卡上顯示「這次規劃花了約 US$0.00x」〔我的決定，研究：Dreamina 回報實際耗點〕。

## 10. 驗收

在 isolated backend + mock 模型、1440×900 下，用 headless 瀏覽器走一遍並截圖（專案慣例，`e2e/`）：
1. 從側欄進畫布：fitView、標題是計畫名、側欄縮成圖示；按全螢幕鈕和 `F`／`Esc` 切換正常。

## 12.5 審稿後補的決定（builder check，2026-11-03）

以下是審稿時實作者會猜的地方，由撰寫者決定〔我的決定，使用者可推翻〕，已對照程式碼：

1. **框的歸屬**：用節點既有的 `shotId`（`src/lib/canvas/graph.ts:206` 已經這樣分 shot 列）決定節點在哪個框，不另存一份狀態。有 `shotId` 的節點只能在自己的框裡拖動，不能拖到別的框；沒有 `shotId` 的節點（Kit、使用者自己加的 Prompt／Upload）放在框外的自由區，可以接到任何 shot。舊存檔照 `shotId` 自動放進框，不需改後端格式。
2. **Kit 的位置與線**：Kit 節點固定在所有框的左邊。分鏡圖是每個框裡最左邊的節點，所以 Kit 的線只穿過框的邊界、不穿過節點，符合 §2 反目標；線照套組規格是淡色。
3. **隱含 shot 文字存在哪**：沿用生成節點既有的 `prompt` 欄位。空白 = 用 shot 的文字（和現在接 Text 線時一樣，在前端由 `graph.ts` 解析出來）；有內容 = 用節點自己的文字。改寫不會回寫 shot list。接上 Prompt 節點時完全取代 shot 文字。套組前綴照舊在後端 `with_prefix`（`backend/generations.py:211`）加在最前面，`MAX_PROMPT` 截短順序不變。
4. **送審按鈕**：還沒有匯出的成片時，上方工具列的「Send for approval」可以按，按了進入全螢幕剪接並停在匯出那一步，旁邊一行字說明「先匯出成片才能送審」。不送不完整的片。
5. **Run all 的範圍**：跳過目前版本有結果且沒有過期的節點、跳過已從計畫刪除的 shot；確認窗只列會花錢的節點。
6. **一張畫布一個 Timeline 節點**：畫布、剪輯專案和成片都是每個 idea（計畫）一份（`backend/media/<ideaId>/cut/`），所以一個 Timeline 節點、一個審閱連結是對的。
7. **預估等待時間**：`gen_models.json` 每個模型加 `typicalSeconds`，第一版用提供商文件或測試時量到的數字，畫面上一律寫「約」。mock 模型用它自己的延遲。

## 13. 風險與未驗證

- Shot 變成框之後，舊存檔與套組規格「套組自動接到每一個分鏡圖」的邏輯都要跟著改；是最容易出錯的地方。
- 「隱含 shot 文字」改變了 prompt 的組法：要確認跟套組規格 §5.3 的前綴、`MAX_PROMPT` 的截短順序沒衝突。
- 預估等待時間沒有真實資料，第一版可能不準。
- 草圖是靜態的；使用者說「等做出來我再去改善」〔使用者〕，所以線與節點的細節（粗細、間距、動畫）預期會在 user test 後再調一輪。
