# Remake 節點畫布 + 剪輯器 設計規格

_2026-11-02。依據：`docs/decision-log.md`（2 Nov 2026 第一條）、研究報告 `pivots/02-content/research/reports/AI 節點畫布與剪輯器 研究.md`（網頁版 https://claude.ai/artifact/LLMAs6dfMBLoYyCqiArreT）、團隊白板。狀態：草稿，待使用者核可。_

標記：**〔使用者〕** = 使用者或團隊說的；**〔我的決定〕** = 撰寫者做的選擇，使用者可推翻；**〔交給實作者〕** = 實作時自行決定。

## 1. 為什麼做、做成什麼

Remake 幫 agency 翻拍爆紅短影音。現在的流程到「shot list → 實拍上傳 → 自動剪片」為止，中間沒有讓人「先看到畫面」的地方，也不能用 AI 補鏡頭。新方向〔使用者〕：

```
Find ideas → Plans 看板 → shot list → 節點畫布 → 剪輯器（右側抽屜）→ 匯出 / 發布
（不變）     （不變）     （沿用）     （新）        （新，取代現在的 Make the video）
```

demo 時要能演完的一條路〔使用者〕：**選一個 shot → 生成分鏡圖 → 轉成影片 → 拖進右邊時間軸 → 剪好出片。**

這是非商業的學生 demo 專案〔使用者〕，所以開源授權不是限制；Claude Max 額度夠用，時程不是限制，分階段做、每階段要驗證〔使用者〕。

## 2. 目標、非目標、反目標

**目標**
1. 節點畫布：shot list 自動長出節點，每個 shot 可以走「AI 分鏡圖 → AI 影片」或「上傳實拍」。
2. 使用者每個生成節點可從 3–5 個精選模型裡選〔使用者〕，生成前看得到價格。
3. 剪輯器（CapCut 等級〔使用者〕）在畫布右側抽屜〔使用者〕，影片節點拖進時間軸〔使用者〕，剪片、文字、字幕、音樂、品牌素材、出片。
4. 出片結果接回現有的核准連結和發布流程。

**非目標（這次不做）**
- Premiere 式多軌時間軸〔使用者〕。
- 核准 Panel 的新設計〔使用者：之後專門做〕。這次只確保成片能接上現有的審閱連結。
- 開放全部模型、使用者自帶 API key、多人同時編輯同一張畫布。
- 手機版畫布編輯（390 寬只需要能看、不壞版；見 §8）。

**反目標（做到了也算失敗）**
- 一個按鈕就悄悄花掉大筆錢：任何會花錢的動作都要先顯示價格；有每日上限。
- 使用者面對一張空白畫布不知道從哪開始。
- AI 生成變成唯一的路：實拍必須一樣順。
- 預覽和成片長得不一樣（這是選 Remotion 的理由）。
- 模型下架就整個功能壞掉（`gpt-image-1` 已發生過）。

## 3. 現況（實作者要知道的）

路徑相對於 `pivots/02-content/app/trend-finder/`。

- 前端 React 19 + Vite + TS，沒有 router；Plan 頁是 `App.tsx` 的 `view === 'plan'` → `PlanScreen`。依賴只有 `react`、`react-dom`、`@dnd-kit/core` 6.3.1。
- 後端 FastAPI + SQLite，`backend/server.py` 掛各模組的 router。
- Shot 型別 `src/types.ts:47`：`time, shot, text?, line?, frameImage?, purpose?, options?, edited?, palette?`。
- 分鏡圖 `backend/storyboard.py`：`POST /api/ideas/{id}/shots/{shot}/frame`，預設免費 SVG 佔位，`FRAME_IMAGE_PROVIDER=openai` 才呼叫 `gpt-image-1`（研究指該模型 2026-10-23 已停用，未實測）。
- 實拍 take `backend/takes.py`：上傳 / 列表 / 選用 / 刪除，檔案在 `backend/media/<ideaId>/`。
- 剪片 `backend/renders.py`、`cutting.py`、`subtitles.py`、`grading.py`：ffmpeg + 本機 whisper.cpp（有逐字時間戳）；`POST /api/ideas/{id}/cut` 非同步出片，產出 `media/<ideaId>/cut/final.mp4`；`cut_review.py` 給審閱連結看成片。
- 花費控管 `server.py:865` `spend(wallet, usd, cap)`：每日每個錢包上限，`DAILY_IMAGE_USD` 預設 0.50。
- i18n：新文案走 `t()`，英文和繁中都要加。
- 開著的 PR #12（Plan 頁分頁）暫停不合併；改版計畫線 A / B 暫停（見 decision log）。

## 4. 畫面

### 4.1 進入點
從**已核可的 plan** 頁進入「畫布」〔我的決定：沿用現有「核可後才能製作」的閘門，避免沒核可就花錢；可推翻〕。畫布是 plan 的一個全寬畫面，有返回 plan 的按鈕。

### 4.2 配置〔使用者選 A〕
- 畫布佔滿主畫面；右上「開啟剪輯」。
- 剪輯器是右側抽屜，約 40% 寬，畫布同時縮窄（不是蓋住）；可收起，收起後畫布恢復全寬。抽屜寬度可拖拉調整〔我的決定〕。
- 抽屜由上到下：9:16 預覽 → 單軌時間軸 → 工具列（剪片、文字、字幕、音樂、品牌）→ 出片。

### 4.3 畫布初始狀態
plan 有 N 個 shot，就自動排出 N 列，每列一個 **Shot 節點**，由上到下照 shot 順序〔我的決定〕。每個 Shot 節點右邊預先接好一個空的「分鏡圖」節點，讓第一步一眼就看得到〔我的決定〕。之後 shot list 增減，畫布同步新增 / 標示已刪除的 shot（不自動刪使用者的生成結果）。

## 5. 節點

| 節點 | 輸入 | 輸出 | 說明 |
|---|---|---|---|
| Shot | — | 文字（台詞、鏡頭描述） | 從 plan 長出，不能刪；顯示 shot 編號、台詞、狀態 |
| Prompt | 文字（可選） | 文字 | 自己寫或改寫 prompt；可沒有，直接在生成節點裡打 |
| 分鏡圖（AI 圖） | 文字（必要）、參考圖（可選） | 圖片 | 選模型、看價格、生成；保留每次版本 |
| 上傳 | — | 圖片或影片 | 上傳參考圖或實拍；影片走現有 takes |
| AI 影片 | 起始畫面圖（必要或可選，依模型）、文字 | 影片 | 選模型、長度、價格；保留版本 |
| 實拍 | Shot、參考影片（可選） | 影片 | 就是現有的 take 清單；分鏡圖 / AI 影片當拍攝參考 |

**連線**
- 依媒體上色（文字 / 圖 / 影片三色），只能接相容的埠〔研究：Runway、Krea〕。
- 圖片接到 AI 影片時，線上標明用途（「起始畫面」或「參考」），因為不同模型意思不同〔研究：Higgsfield〕。
- 改了上游節點，下游節點標「過期」，**不自動重跑**（重跑要花錢，使用者按了才跑）〔我的決定〕。

**版本**
每次生成新增一筆紀錄，不覆蓋；節點顯示目前選用的那一筆，可以往回切〔研究：這是競品最弱、最適合 demo 的點〕。

**成本顯示**
- 每個生成節點在按鈕旁顯示「約 US$x.xx」。
- 提供「整條跑完」（這個 shot 從分鏡圖到影片），按下先列出總額再確認〔研究：Weave、Krea〕。
- 撞到每日上限時顯示剩多少額度、已完成的保留、沒做的不收錢。

## 6. 模型

- 每個生成節點有模型下拉，選單只放精選清單〔使用者：3–5 個〕，每個標「便宜 / 平衡 / 最好」和每次價格。
- 模型清單放在後端設定檔（JSON，避免新增 pip 依賴）〔我的決定〕：id、顯示名、類型（image / video）、提供商、價格公式、支援的輸入（起始畫面、參考圖、長度選項）、標籤。加減模型只改這個檔。
- 起始清單〔我的決定，價格為 2026-11-02 研究快照，實作前要上官方頁核對〕：
  - 圖片：Nano Banana 2（Gemini 直連，約 $0.067/張，平衡）、Seedream 4.5（fal，約 $0.04/張，便宜）、Nano Banana Pro（Gemini，約 $0.134/張，最好）。
  - 影片：MiniMax Hailuo / H3（fal，約 $0.05/秒，便宜）、Kling（fal，約 $0.07–0.14/秒，平衡）、Veo 3.1（Gemini 或 fal，約 $0.40+/秒，最好）。
- **Mock 模型**：一個免費的假提供商，回傳佔位圖和用 ffmpeg 產生的測試片，延遲幾秒、可模擬失敗。開發、測試、E2E 全部用它；demo 前沒有 key 時也能完整演。〔我的決定，必要〕

## 7. 後端：生成工作

- **轉接層**：每個提供商一個薄 adapter（`submit` / `poll` 或 webhook / `fetch_result`），共用一個介面；先做 mock、fal、Gemini 三個〔我的決定，依研究〕。
- **工作表**：每次生成一列（id、idea、node、模型、輸入、輸入雜湊、狀態 queued/running/done/failed、預估價、實際價、檔案路徑、建立時間）。生成紀錄只增不改，就是 §5 的版本。
- **檔案**：完成後一小時內一定要下載回 `backend/media/<ideaId>/gen/`（提供商的網址會過期）。
- **花錢**：送出前用 `spend()` 先扣預估價（新錢包，例如 `gen_image`、`gen_video`，各有每日上限環境變數），失敗退回。webhook 可能重送，處理要冪等。
- **前端輪詢**：沿用現有剪片的 2 秒輪詢模式，或 SSE〔交給實作者〕。
- 本機開發沒有公開網址收 webhook，所以先用輪詢〔我的決定〕。

## 8. 剪輯器

- **引擎：Remotion**〔使用者選選項 A〕。預覽用 Remotion Player，成片用同一份 composition 出片。出片要在伺服器跑 Node + Chromium（`@remotion/renderer`，從 FastAPI 用子程序呼叫）還是用瀏覽器端出片〔交給實作者，先做一次 30 秒 9:16 的計時實驗再定，研究報告「下一步」第 5 項〕。
- **時間軸**：單軌，片段由左到右〔使用者：不做多軌〕。另外有一條文字 / 字幕疊加層和一條音樂層，但都不是可自由排列的軌道〔我的決定〕。
- **放片段**：從畫布把影片節點（AI 影片或實拍 take）**拖進時間軸**〔使用者〕，放哪就排哪。時間軸空的時候顯示「全部依 shot 順序放入」按鈕〔我的決定〕。
- **片段引用素材，不複製**：時間軸記住「哪個節點、哪一版」。畫布上該節點換了版本，時間軸上的片段顯示「有新版本，套用？」〔我的決定〕。
- **工具**：
  - 剪片：拖頭尾修剪、在播放頭分割、刪除、拖動排序。
  - 文字：加一段文字、改字、位置用預設幾個（上 / 中 / 下），字型和顏色從品牌素材挑。
  - 字幕：用現有 whisper.cpp 的逐字時間戳自動產生，可以改字；TikTok 式分組用 `@remotion/captions`。
  - 音樂：上傳一首、調音量、勾選授權（沿用現有規則）。
  - 品牌：每個 client 一組 logo、字型、主色〔我的決定：先存在 client 的 Brief 上〕。
  - 出片：9:16 MP4，進度和預覽；成功後成為這個 plan 的成片，接上現有審閱連結（`cut_review.py`）和發布。
- 現有 ffmpeg 管線改成只負責清理每段 take、轉錄；舊的「Make the video」在新剪輯器能出片後移除〔我的決定〕。

**剪輯專案 JSON（形狀示意，細節交給實作者）**
```json
{
  "fps": 30, "width": 1080, "height": 1920,
  "clips": [{ "id": "c1", "source": { "kind": "generation", "id": "gen_42" }, "in": 0.0, "out": 3.2 }],
  "texts": [{ "id": "t1", "text": "3 天學會", "start": 0.5, "end": 2.5, "position": "top" }],
  "captions": { "enabled": true, "words": [{ "text": "hello", "start": 0.12, "end": 0.40 }] },
  "music": { "file": "music.mp3", "volume": 0.4 },
  "brand": { "logo": "logo.png", "font": "Noto Sans TC", "color": "#1d5fbf" }
}
```
`source.kind` 是 `generation`（畫布生成）或 `take`（實拍）。

## 11.5 審稿後補的決定（builder check，2026-11-02）

以下都是〔我的決定〕，使用者可推翻。

1. **成片只有一支。** 新剪輯器出片寫到現有的 `media/<ideaId>/cut/final.mp4`（同一路徑、同一筆 cut 紀錄），所以審閱連結和發布不用改。P3 期間舊的「Make the video」仍在，兩者都寫同一個檔、後寫的算數；P4 移除舊按鈕。新時間軸不從舊的自動剪片長出來。舊管線的「剪掉口頭禪 / 停頓」只套在實拍 take 上，AI 片段不套；調色（grade）先不套在 AI 片段。
2. **片段自帶的聲音保留**，每個片段有音量和靜音；音樂層另外有音量。Veo 這類有聲模型的聲音照用。
3. **Shot 加穩定 id。** `Shot` 新增 `id`（舊 plan 讀取時補上、存回），畫布節點、生成紀錄、剪輯片段都用 shot id，不用順序。shot 被刪時，它的節點標「已從 shot list 移除」，生成結果保留。現有以 `{shot}` 編號為路徑的 API 照舊能用。
4. **舊資料帶進畫布。** 既有的 `frameImage` 變成該 shot 分鏡圖節點的第一個版本；既有 takes 出現在該 shot 的實拍節點裡。之後 Plan 頁顯示的分鏡圖 = 畫布上該節點目前選用的版本（只有一個來源）。舊的分鏡圖端點改成走新的生成工作和模型清單，不保留兩條生圖路。
5. **模型不支援的輸入：** 連線時就擋住並說明原因（例如「這個模型不吃參考圖」），不默默丟掉。模型最長秒數短於 shot 長度時，選最接近的可用長度並提示，剪輯時再修。所有影片模型只列支援 9:16 的；不支援的不放進清單。
6. **「全部依 shot 順序放入」的選片規則：** 每個 shot 取一支「主片段」：有選定的實拍 take 就用 take，否則用 AI 影片節點目前選用的版本；都沒有就跳過並提示。使用者可以在節點上按「設為這個 shot 的主片段」改掉。手動拖曳不受此規則限制，一個 shot 可以拖進多段。
7. **錢包範圍：** 全 app 共用的每日上限（新錢包 `gen_image`、`gen_video`，環境變數 `DAILY_GEN_IMAGE_USD`、`DAILY_GEN_VIDEO_USD`），demo 是同一個團隊在用。畫布 JSON 存檔帶版本號，後寫的人若版本過期就提示重新載入，不做多人合併。
8. **退款：** `spend()` 旁新增退款函式（扣回當日金額，不低於 0）。提供商回報失敗才退；輪詢逾時但提供商仍可能收費的情況標為「狀態不明」、不退，畫面顯示「可能已收費」。
9. **demo 機器：** 用目前跑 demo 的 Mac mini（已有 Node）。Remotion 實驗在這台做，驗收門檻：30 秒 9:16 出片 2 分鐘內完成，中文字型（Noto Sans TC）和聲音正確。超過就改瀏覽器端出片或回到 ffmpeg 出片。
10. **mock 片段規格：** 1080×1920、30fps、H.264 + AAC（有聲音的測試音）、每秒一個關鍵畫格，用 ffmpeg 的 `testsrc2` + `sine` 產生（不需要缺少的濾鏡）。

## 11.6 旁白與字幕來源〔使用者，2026-11-02〕

- **預設（免費）：** 沒有人聲的片段，用該 shot 的台詞（`line`）當字幕，平均排在片段的時間內。只有字、沒有聲音。
- **使用者可以自己選加旁白**，兩種：
  1. **AI 配音（ElevenLabs，要花錢）：** 唸台詞產生旁白，按下前顯示價格，走 §7 的生成工作和錢包上限（新錢包 `gen_voice`）。ElevenLabs 列在模型清單裡，類型 `voice`。
  2. **自己錄（免費）：** 在剪輯器裡用麥克風錄（瀏覽器 MediaRecorder），或上傳一段音檔。
- 有旁白之後，用現有 whisper.cpp 轉出逐字時間，字幕改成跟著旁白走。
- 剪輯專案 JSON 多一層 `voiceover`（每段：來源 tts / recording / upload、檔案、起點、音量）。
