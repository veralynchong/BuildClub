How to stop and restart

Stop: press Ctrl-C in the terminal that runs it, or kill 88173 (the uvicorn PID). The script then deletes its temp copy. Every restart begins with a fresh database, so the demo account is created again and earlier plans are gone.

cd /Users/veralynlavignechong/Developer/projects/buildclub-minchia-backend
TF_VENV="$PWD/pivots/02-content/app/trend-finder/backend/.venv" bash bin/isolated-backend.sh 8797 --demo-data --user test@example.com:<password>

If the frontend code changes, run npm run build in pivots/02-content/app/trend-finder before you restart.

Open issues for Minchia

  1. Plans made from seeded Research rows are hidden in this setup. The script sets APIFY_TOKEN=dummy, so /api/health returns live: true and the app runs in live mode. Then shownIdeas (src/App.tsx:863) drops every plan whose video is not live. The seeded Evergreen rows are sample videos (for example y2 in src/data/sample.ts). So the walkthrough in note 2 ("make a plan from a row") stops at an empty Plans board. Only link- videos get through the filter. Two possible fixes: make demo mode not count as live, or let demo or sample plans through the filter.
  2. The toast says something that isn't true. "Sent to Plans, in Still planning" shows up even when the plan won't appear on Plans.
  3. Approver name is hard-coded. "Annie approved this" shows even though the reviewer is the signed-in E2E Tester.
  4. Demo data has no breakdowns. --demo-data found 0 breakdowns, because no worktree on this Mac has a backend/jobs folder. The search fallback path is still the hard-coded /Users/tommy/.... Pinned searches (7) did load.
  5. The default TF_VENV points at Minchia's machine (/Users/tommy/Desktop/BuildClub/...). It would be better to default to the checkout's own backend/.venv.
  6. npm allow-scripts warning. The esbuild and fsevents install scripts didn't run. The build still worked, but they may need npm approve-scripts on other machines.
